# D5.9 HID Stress / Adverse-I/O Hardening

**Release:** 0.5.9-alpha  
**Purpose:** make the remaining HID-stress Stable gate executable, observable and fail-closed without pretending that synthetic tests equal physical wheel certification.

## What changed

### 1. Real transport metrics

The single native Windows HID writer now records process-lifetime diagnostics for:

- handle opens / open failures;
- output writes / successful writes / failed writes;
- deadline timeouts;
- partial writes;
- `CancelIoEx` requests;
- fail-closed poison events;
- OVERLAPPED -> `HidD_SetOutputReport` compatibility fallbacks;
- closes, last backend, last error, last/max write latency.

The counters are visible in **Kalibrieren & Lernen -> D5.9 HID Stress / adverse I/O** and in **Engine Health**.

### 2. Ambiguous writes are now always fail-closed

D5.9 closes an adverse-I/O gap found while reviewing the stress path. A partial `WriteFile` completion or a failed `GetOverlappedResult` means LogiMate cannot prove what reached the wheel. Those outcomes now poison and close the transport immediately. The handle cannot be reused or silently retried.

The existing rule remains unchanged: only synchronous `ERROR_INVALID_FUNCTION`, `ERROR_NOT_SUPPORTED` and `ERROR_INVALID_PARAMETER` may switch to the bounded HidD compatibility backend, because those errors prove the OVERLAPPED write was not queued.

### 3. Deterministic software stress

The in-app software test performs 10,000 iterations and checks:

- safe non-motor range-report construction;
- exact compatibility-fallback errno policy;
- deadline conversion;
- adverse-I/O error classification;
- fail-closed poison semantics.

`RunInternalSelfTests` also includes a smaller D5.9 policy-stress pass, so Engine Health catches regressions continuously.

### 4. Guided real-wheel stress

The new D5.9 assistant provides two physical/runtime probes:

1. **100-cycle normal stress**
   - holds the central non-motor output lease;
   - repeatedly reopens the selected native HID path;
   - writes only the wheel's already-selected range (idempotent, non-motor);
   - closes the transport each cycle;
   - samples live Direct-HID input during the run;
   - exports JSON + Markdown evidence.

2. **USB-yank adverse-I/O window**
   - runs the same non-motor reopen/write cycle for an approximately ten-second window;
   - the user removes USB during the window;
   - LogiMate expects a real HID failure/disconnect;
   - the central lease must still be released;
   - a subsequent normal stress run after reconnect confirms the recovered path.

No Constant Force, Spring, Damper, Friction or Autocenter command is generated by the D5.9 live probe.

## Stable boundary

D5.9 deliberately keeps `docs/HARDWARE_CERTIFICATION.json -> hidStressValidated=false`.

Synthetic/software PASS proves only the policy and implementation. Stable still requires reviewed evidence from physical G25/G27/DFGT hardware, including normal stress, USB removal/reconnect and adverse I/O behavior. The repository flag is promoted only as an explicit release-review action.
